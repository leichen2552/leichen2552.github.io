# 赞赏收款码与音乐署名展示修复设计

## 问题与根因

文章页赞赏区域仍会生成支付宝和微信图片标签，但 `site.config.json` 中的 `donate_alipay` 与 `donate_wechat` 均为空字符串，因此线上 HTML 输出 `src=""`，浏览器无法显示收款码。仓库根目录现有的 `alipay.jpg` 与 `wechat.jpg` 文件完好，构建脚本也会复制它们，线上访问均返回 HTTP 200。

## 方案

- 保持现有赞赏按钮、悬浮布局和两张收款码图片不变。
- 将支付宝路径配置为 `/alipay.jpg`，微信路径配置为 `/wechat.jpg`。
- 在站点校验脚本中检查：启用赞赏时配置不得为空、源文件与构建文件必须存在、生成的文章 HTML 必须引用这两个根路径。
- 不修改图片内容，不引入第三方资源，不增加页面首屏网络请求；图片仍只由现有赞赏区域按浏览器规则加载。

## 音乐署名展示

当前页脚直接铺开五首音乐、镜像文件和许可证链接，信息过长，破坏页脚视觉层级。为继续满足 CC BY 4.0 署名要求，同时保持页面简洁：

- 将完整署名列表放入原生 `<details>` 折叠区，默认关闭。
- 页脚默认只显示低调的“音乐版权”入口，不显示曲目和文件链接。
- 用户主动展开后，仍可查看每首曲目、Wikimedia Commons 文件来源、作者及 CC BY 4.0 许可证。
- 使用原生 HTML 交互，不增加 JavaScript、第三方依赖或首屏网络请求。
- 校验脚本要求折叠入口存在、默认未展开，并保留所有署名链接。

## 验证

1. 先添加回归校验并确认它因空路径失败。
2. 补齐配置后运行完整构建与校验。
3. 本地检查文章页生成的两个 `img src`，并确认图片返回正确 JPEG 类型。
4. 本地确认页脚默认只展示“音乐版权”，完整署名仅在展开后出现。
5. 通过 PR 合并并等待 GitHub Pages 成功部署，再检查线上文章、两张图片和折叠署名。
